# Aethelark Roadmap — Modularity & Human Emulation

**Created:** 2026-08-02

## The Filter

Every decision in every plan below runs through one question:

> **Is this getting us closer to human emulation?**

A human employee sitting at your desk perceives interface *structure*, not pixels.
They use whatever tools are already on the machine rather than demanding you buy
new ones. They tell you what they're doing and what it costs. They don't crash
your computer.

Where a task doesn't clearly serve that, it gets cut or deferred.

## The Discipline

Non-negotiable, per the user's instruction:

1. Upgrade one thing.
2. Test it — full suite green, plus new tests proving the new behavior.
3. Merge to `main`.
4. Repeat.

Concretely:
- Each **task** ends in a passing test and its own commit.
- Each **plan** ends in a merge to `main` with the full suite green.
- No plan starts until the previous one is merged.
- `main` is always shippable. There is never a half-migrated state on `main`.

Baseline at roadmap creation: **330 tests passing**, working tree clean.

## The Sequence

Ordered by the filter, not by architectural tidiness.

### Plan 1 — Fast Hands: accessibility-first grounding ← START HERE
**File:** `2026-08-02-fast-hands-grounding.md`

Replace the "screenshot the whole screen and ask a VLM for x,y" grounding path
with a tiered resolver: accessibility tree first (local, milliseconds, exact
coordinates), cache second, vision last.

*Filter:* Directly. This is the difference between an agent that squints at
pixels and one that perceives an interface. It is also the single largest
latency win available in the hands path.

*Independent of:* everything. Purely additive, no router dependency, `main.py`
untouched.

**Measured baseline to beat:** 93ms local overhead, 188KB upload, one full VLM
round-trip per element lookup. Zero tests exist for this path today.

### Plan 2 — Declare the human-showcase boundary
**File:** TBD — `2026-08-__-ui-contract.md`

Write a `Protocol` for the interface `AethelarkLive` expects of a UI —
`write_log`, `set_state`, `set_speaking`, and the rest — and have both
`main.py`'s native UI and `aethelark_web.py`'s `WebShellUI` (`:293`) assert
conformance against it.

**Purely additive. Moves no code.** It makes an implicit, duplicated,
hand-rolled contract explicit, and catches drift the moment it happens.

*Filter:* Yes, and more directly than it first appears. This contract **is the
human-showcase boundary** — the single place where the eagle's internal state
gets translated into something a person perceives. It is currently undeclared
and written out by hand twice. Declaring it is declaring where the machine
stops and the human begins.

*Why here and not last:* every remaining plan adds a UI surface — the VRAM
meter in Plan 4, the agent lane labels in Plan 5. If the contract isn't
declared before those, each one hand-rolls its own glue in two places and
Plan 7 has strictly more to untangle. The duplication compounds; declaring it
early is what stops the bleeding.

*Cost of the reorder:* "works on someone else's machine" slips by one plan.
Acceptable — shipping is currently from a checkout, to ourselves.

---

### Plan 3 — Capability audit & the three cases
**File:** TBD — `2026-08-__-capability-audit.md`

Boot-time detection of hardware, installed agent CLIs, GUI apps, and API keys,
fused into one profile, resolved into one of three cases.

**Precedence (confirmed by the user):**

| Priority | Case | Detected | Behavior |
|---|---|---|---|
| 1 | **Subscription CLIs** | `claude`, `agy` live | Delegate hard work. HARDCORE swarm. Eagle conducts. |
| 2 | **Metered API** | Anthropic / OpenAI / OpenRouter key | Use SDKs. Eagle does the work itself. |
| 3 | **Local brain** | Ollama / LM Studio up | Local SDK, with VRAM headroom reserved for the user's apps. |

Flat-rate beats metered: a user with Claude Code *and* an OpenRouter key routes
to Claude Code.

*Filter:* Indirectly but necessarily. A human employee works with what's already
on your desk. This is what lets the eagle do that on any machine.

*Key-discovery locations found while researching prior art:* OpenCode stores
credentials in `~/.local/share/opencode/auth.json` and config in
`opencode.json`. If a user has OpenCode configured, their provider keys are
already on disk in a known place — the audit should read it rather than asking
the user to paste a key they've already entered once.

*Constraint discovered:* the audit cannot block the pill. `nvidia-smi` + `lspci`
alone are ~400ms. Boot optimistic from cache, stream the profile in behind it.

### Plan 4 — VRAM governance for the local case
**File:** TBD

Runtime guard so the swarm never starves the machine. **Not** `Semaphore(1)` —
that serializes the safe case and still permits the dangerous one. The real
rule is a cap on *resident distinct models* plus a request queue depth.

Two agents sharing one resident model is safe. Two agents on two different
models is what OOMs the GPU.

`machine_profile._recommend` (`actions/machine_profile.py:114-117`) already
budgets 75% of VRAM / 55% of RAM with exactly this intent. It needs to govern
the swarm at runtime, not only the onboarding recommendation.

*Filter:* Yes — a human employee doesn't freeze your machine to finish their task.

---

### Plan 5 — Backend-aware agent identity
**File:** TBD

`aethelark_web.py:596` hardcodes CLI display names. The same logical agent must
render differently depending on how it's actually executing:

| Backend | HARDCORE lane shows |
|---|---|
| CLI subprocess (case 1) | `Claude Code` · `Antigravity CLI` |
| SDK / metered (case 2) | `Claude Agent` · `Antigravity Agent` |
| Local model (case 3) | `Gemma Agent` · whatever model is resident |

Labeling an SDK-backed agent "Claude Code CLI" is a lie about what's running.

*Filter:* Yes — honest reporting of what's doing the work.

### Plan 6 — Provider-agnostic text brain
**File:** TBD

Abstract `core/llm_client.py` behind one interface with Gemini / OpenRouter /
Anthropic / OpenAI / Ollama adapters. Unblocks case 2.

*Shape borrowed from OpenCode* (which reaches 75+ providers via the Vercel AI
SDK + models.dev): keep the **model catalog separate from the client code**,
make **OpenAI-compatible the universal fallback adapter**, expose a
**`baseURL` override** as the escape hatch for proxies and self-hosted
endpoints, and allow **per-agent model selection**. We take the shape, not the
dependency — the Vercel AI SDK is Node-only, and calling models.dev at runtime
would make model selection depend on someone else's uptime. Vendor the
catalog; refresh only when asked.

Voice stays Gemini Live — Anthropic has no realtime voice API, and the session
loop is welded to the Gemini SDK types. Abstracting voice means rebuilding
barge-in, `call_epoch` fencing, vision injection, and the wedge watchdog. Not
worth it until there's a second voice provider actually worth having.

*Note:* Plan 1 removed one hardcoded Gemini dependency (`_screen_find`) as a
side effect, which shrinks this plan's surface.

### Plan 7 — Decompose `AethelarkLive`
**File:** TBD

Extract collaborators out of the 1,535-line god object (`main.py:825-2360`) —
the session loop, tool dispatch, audio. The UI contract it needs to land
against was already declared in Plan 2, so this plan only has to *move* code,
not also *discover* the interface while moving it.

**Deliberately last.** This touches the four hardest-debugged things in the

the time we get here, Plans 1-6 will have built characterization tests around
the surfaces it touches, which is what makes the refactor safe rather than
brave.

*Filter:* Indirectly. It's what makes every subsequent human-emulation feature
cheap to add.

## Deferred (tracked, not scheduled)

- **Full `runtime_paths` migration** — 14+ call sites computing
  `config/api_keys.json` independently. Blocks packaged installers
  (`.exe`/`.dmg`/`.AppImage`). Not blocking today because shipping is from a
  checkout. New code written in Plans 1-7 must use `runtime_paths` so the
  problem stops growing.
- **Machine-native agent communication** — dense structured state on a shared
  blackboard instead of prose re-derivation. Real wins are 2-20x and come from
  *token count*, not byte encoding. Binary/zero-copy protocols target
  serialization, which is 0.0001% of the loop (measured: 1.44µs to parse a tool
  call vs ~1-3s per model turn). Revisit when we own both ends of the wire.
- **Acquisition** — the eagle installing a free BYOK CLI and pointing it at a
  key the user already has, collapsing case 2 into case 1. Parked pending a
  product call on whether the eagle should install software.
